# 低流量高转化：补供给后规模响应

> 本案例是 **Demo 模拟案例**（synthetic case），用于说明分析方法，不对应任何真实线上商品、真实运行数据或真实线上效果。全篇只做相对描述，不使用具体数值。

## 背景

某个高频低价类商品的交易效率一直不错，但播放量在商品池里处于后段，订单绝对量很小。团队在讨论要不要放弃这个商品。两个周期之后，情况发生了变化——这里记录的是**补供给之后得到响应**的那种走向。

## 观察到什么

- 效率层（OPM / GPM）稳定，没有走弱迹象；
- 流量层明显偏低，且与池内多数对象有差距；
- **发布状态：前一个周期该商品没有新增发布，后一个周期恢复发布**；
- 恢复发布后，播放量上行，订单量跟随上行，效率层只出现小幅稀释。

## 可能解释

1. **供给中断造成的规模不足**——与观察一致：效率没变、量随发布恢复而回来；
2. 商品吸引力问题——不一致：吸引力差通常先在效率层表现出来；
3. 承接问题——不一致：承接断了会同时压住效率指标；
4. 分发资格受限——无法排除，但当前没有对应字段可查。

## 如何继续区分

1. 先确认问题形态：效率尚可 + 流量低 = 规模层受限，不是质量层受限（见 GUIDE04、GUIDE11）；
2. 查发布状态跨期变化：这里查到了"上一期未发布、本期恢复发布"；
3. 查集合位置：确认是个体低还是全池低——若是全池同步低，个体解释要收窄（GUIDE13）；
4. 恢复供给后做两期对比，看流量与订单是否响应：**响应成立**才支持"供给中断是主因"这个方向；
5. 观察稀释：扩量后效率小幅下降属常见，明显下降则说明限制不止在供给。

## 与相近案例的分界

与 CASE05 表面上完全一样（都是"效率好、流量低"），关键差别只有两条：**本案例发布状态确实发生了收缩后恢复**，且**规模随供给响应**。CASE05 的供给本来就没断、全池同步下行，因此同样的补量动作没有效果。判定条件不同时，不要把两个案例的结论互换。

## 得到什么经验

**"有效率信号但规模不足"值得先验证供给约束，但"验证"的含义是做出一次供给变化并观察响应，不是直接假设供给就是原因。**

补量之所以在本案例有效，是因为它对准了一个查证过的收缩。没有这一步核对，"补内容"就只是一个听起来合理的动作。

## 不能类比的条件

- 供给本来就正常（没有收缩证据）→ 补量的边际价值不明，见 CASE05；
- 效率层同步走弱 → 问题形态变成"量与质都弱"，应先查吸引力与承接；
- 从未形成任何交易信号 → 属于冷启动判断，先确认机会三层（GUIDE09）；
- 全池流量同步下行 → 个体解释要收窄，先处理共同因素；
- 两期窗口不可比或关键值为 unknown → 先处理口径问题（GUIDE14）。
