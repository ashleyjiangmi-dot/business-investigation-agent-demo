# 数据不足时的收束：三条限制同时出现怎么办

> 本案例是 **Demo 模拟案例**（synthetic case），不对应任何真实线上商品或真实运行数据。全篇只做相对描述，不使用具体数值。

## 背景

问题是"这个商品最近表现怎么样，还值得继续投入吗"。查下来同时遇到三条限制：想比的周期之一没有记录；有记录的周期里某项效率指标分母为零；另一周期存在同一对象同一周期的两条互相矛盾的记录。本案例示范的是**这种情况下合格交付长什么样**。

## 观察到什么

- 目标周期对：一个有记录、一个**无记录**（该对象该周期没有数据）；
- 有记录的周期里，播放量与订单量正常，成交额效率指标返回 unknown（分母为零）；
- 另一个周期出现**同键双记录且内容互相矛盾**，涉及它的两期比较被直接阻断；
- 集合比较时，该对象因为无可用值被列入缺失组；
- 预算内仍可继续查询，但**继续换口径查不会让这三条限制消失**。

## 可能解释

这里没有经营层面的解释可做——**问题不在商品，在证据**。三种限制各自的含义不同，必须分开处理：

- 缺周期：结论不能覆盖那一段时间，也不是"该周期表现为零"；
- 零分母：该指标在该周期不可用，可用合计层指标替代但要注明是替代口径；
- 记录冲突：涉及这些记录的任何变化结论都不成立，需要先解决数据来源问题。

## 如何继续区分

1. 先把可查的查完：换一个确实有记录的周期做对比、把合计层指标读全、做一次集合比较确认缺失范围；
2. 给每条限制归类（范围不足 / 字段不存在 / 值不可用 / 记录冲突，见 GUIDE14），不要合并成"数据不全"；
3. 明确每条限制分别卡住了哪个结论：缺周期卡住趋势；零分母卡住效率判断；冲突卡住所有基于该键的变化；
4. 输出分层交付：
   - **已证事实**：有记录周期的合计层读数与集合位置；
   - **候选因素**：仅列可查方向，不写无证据的原因；
   - **边界与下一步**：需要什么数据或哪条记录被修正之后，才能回答原问题；
5. 不用"整体表现一般"这类含糊表述掩盖三条限制——它会把"不可知"包装成"已知"。

## 得到什么经验

**数据不足时的正确交付是缩小问题范围，不是降低表述精度。** 三条限制各自卡住一部分结论，剩下能说的仍然要说清并绑定证据；说不了的部分要指出"要说什么才需要哪些数据"，这样下一次提问才可能推进。把缺口写成"这个商品看起来不太好"，是最省事也最没用的结果。

## 不能类比的条件

- 只有一条限制且不影响问题主干（例如缺的是不关心的周期）→ 直接改问题范围即可；
- 数据齐备但方向矛盾（量涨效率跌）→ 属结构变化，不是数据不足（GUIDE11）；
- 限制来自窗口不可比 → 先处理可比性，与"无记录"不同因（GUIDE10）；
- 预算已耗尽 → 属处理边界，要如实登记为未完成，不能表述成"查过之后没有发现"。
