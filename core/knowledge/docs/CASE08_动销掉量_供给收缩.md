# 动销掉量（一）：供给收缩造成的下滑

> 本案例是 **Demo 模拟案例**（synthetic case），不对应任何真实线上商品或真实运行数据。全篇只做相对描述，不使用具体数值。

## 背景

一个持续有动销的商品，最近两个周期订单量明显下滑。

## 观察到什么

- 订单量两期下滑；
- **发布状态：上一周期没有新增发布，再前一个周期有**；
- 播放量随供给同步下滑；
- 效率层（OPM / GPM）基本稳定，没有同步恶化；
- 集合内其他对象没有同步下滑，个体跌幅明显大于集合。

## 可能解释

1. **供给收缩**——三层证据同向（发布停 → 播放降 → 订单降），且效率没坏；
2. 商品热度衰退——不能排除，但缺少跨期状态变化支持，且通常效率层也会走弱；
3. 价格变化——当前数据域没有价格跨期变化，此方向不可证；
4. 承接问题——与效率层稳定不一致。

## 如何继续区分

1. 先看供给：发布状态是否跨期收缩（这是本案例唯一有明确证据的层）；
2. 再看流量与订单是否跟随同向：只有订单掉、流量与效率都不掉，就不是供给问题；
3. 与集合对照，排除共同下行（GUIDE13）；
4. 恢复供给并观察规模是否回补——**回补才构成对"供给是主因"的实证支持**，否则解释要重开；
5. 明确不可证部分：素材、内容质量、价格、券与库存都无字段。

## 与相近案例的分界

与 CASE09 同为"历史有动销后掉量"。本案例**发布状态有明确收缩**，CASE09 发布正常、流量稳定，只剩效率或更后段环节可疑，而它最像的原因（价格回升）在 Demo 里根本查不到。分界条件是"供给有没有真的断"，不是"掉量幅度有多大"。

## 得到什么经验

**供给变化可以优先核对，但发布中断与掉量同时出现不证明因果。** 恢复供给后，仍要观察规模是否回补、效率是否稳定，不能把恢复动作本身当成归因成立。

## 不能类比的条件

- 发布状态没有变化 → 参考 CASE09，不要在供给层找原因；
- 效率层同步恶化 → 转承接与吸引力调查（GUIDE05）；
- 全池同步下滑 → 个体解释要收窄（GUIDE13）；
- 商品从未有过动销 → 属于冷启动判断（GUIDE09）。
