# 到店服务与长履约品类的经营例外

## 适用范围（先读这一节）

- **适用**：需要到店使用的服务型商品、限时/限门店/限时段使用的券类商品、保质期极短或配送范围受限的商品、含多项实物与非餐饮权益的组合套餐。
- **不适用**：高频低价、线上下单即时可用的常规商品（多数奶茶、西快单品、小食）。对这些商品，通用的"高流量低转化先查承接"顺序成立（GUIDE05）。

## 先把口径钉住：本域看的是支付订单

- M1 订单量与 M4 OPM 统计的是**支付订单**（`paid_orders`），也就是"用户付了钱"这个动作发生的周期；
- 本地生活是两段式交易：**先付款，后到店核销**。核销发生在付款之后，**核销早晚不会改变支付订单所属周期**；
- 因此"这个商品核销窗口长"**不能**用来解释"它的支付订单在这两个周期里少"——那是把链条后段的延迟搬到链条前段的读数上，因果链错位。

影响付款的可能因素有两类：**付款时点后移**，或**可售条件阻止下单**。

## 怎么理解

### 例外一：决策链更长，支付订单本身可能晚发生

到店、高客单、限定条件复杂（要用哪张券、能不能叠加、哪家店可用、要不要预约）的商品，用户看完内容往往不当期付款，需要先确认场景与可用范围。这条机制**确实会推迟支付订单**，所以"把观察窗口延长到后续周期再看"是有意义的检验动作。

延长观察只能看到后续周期是否出现支付订单，支持或削弱决策链假设，**不构成对核销、券或门店原因的证明**。

### 例外二：可售范围与使用门槛会直接挡掉下单

公开规则里普遍存在**下单时就能撞上的门槛**：仅限部分门店（明确排除交通枢纽、服务区、景区店）、指定时段供应、不与其他优惠同享、配送只覆盖指定城区、保质期两天。

这类限制的作用点在**付款之前**：用户有购买意愿，但自己所在位置、时间或使用条件对不上，于是没有产生支付订单。它的表现与"卖点没讲清楚""价格没吸引力"完全相同，处理方向却不同——前者要改内容的**人群与场景匹配**，后者才轮到改商品与价格。

### 例外三：组合套餐不是单品，别用单品尺子量

含多项内容与非餐饮权益的套餐（餐饮 + 影票 + 礼盒这类），客单高、可用场景分散，单位播放折算出来的效率天然与单品不可比。这是**口径问题**，不是经营好坏问题（另见 GUIDE16 的品类量级、GUIDE12 的标价与人均之分）。

## 常见情况

- 高流量 + 周期内支付订单少 + 商品有明显使用限定 → 先按"决策链 / 可售门槛"两种**可能挡在付款前**的方向列假设，并延长观察看后续周期是否补出支付订单；
- 延长观察后支付订单确实出现在更晚周期 → 支持决策链假设（仍不是证明），仍不该直接动价格与卖点；
- 延长观察后始终没有支付订单 → 例外解释被削弱，回到 GUIDE05 的通用承接与吸引力排查；
- 有订单但看不到"用没用" → 本域没有核销字段，该问题在当前系统里不可答，不要转写成"转化率低"；
- 高频低价即时消费品套用本篇 → 误用，回到 GUIDE05。

## 建议继续看什么证据

- 商品身份与类目：判断是否落在本篇适用范围内（`catalog` 与对象信息可查）；
- **该商品在后续周期是否出现支付订单**（`op=value` 逐期、或跨期 `op=diff`）：这是区分"付款晚"与"没有需求"的唯一可操作办法；
- 与同品类对象比较，不与全池或其他品类比较（GUIDE13、GUIDE16）；
- 发布状态与流量方向：先排除供给与流量问题（GUIDE15）；
- **加购、咨询、决策时长、券使用规则、可用门店范围、核销时间、核销率、退款、保质期、库存与履约能力：当前数据域都没有字段**。相应机制只能列为待验证假设。

## 可考虑的经营方向

- 确认对象落在例外范围 → 先延长观察窗口并核对是否出现支付订单，再决定是否转承接调查；
- 有范围/人群不匹配的迹象 → 内容侧调整人群与场景表达（作为假设，无字段可证）；
- 组合套餐 → 与同类组合商品比较，不换算成单品效率；
- 例外不成立（对象是高频低价即时消费），或延长观察后仍无支付订单 → 回到通用顺序，停止补量并查承接。

## 不能支持的判断

- 不能因为"到店类商品都慢"就给某个低订单商品豁免，必须先确认它落在例外范围且延长观察后确有支付订单；
- 不能把本篇当成品类通用规则扩展到全池；
- 不能用延长观察无限推迟判断：窗口延长后仍无信号，回到 GUIDE07 的降级判据。
