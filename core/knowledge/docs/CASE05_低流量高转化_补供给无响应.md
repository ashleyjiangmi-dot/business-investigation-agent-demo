# 低流量高转化：补供给之后仍然没有响应

> 本案例是 **Demo 模拟案例**（synthetic case），不对应任何真实线上商品或真实运行数据。全篇只做相对描述，不使用具体数值。

## 背景

另一个商品的外观与 CASE04 几乎相同：交易效率不错、播放量在池内靠后、订单绝对量小。团队按 CASE04 的经验补了一轮供给，两期之后规模没有起来。本案例记录的是**补供给无效**的那种走向。

## 观察到什么

- 效率层（OPM / GPM）稳定；
- 流量层低，且补量后没有明显变化；
- **发布状态：该商品在相关周期内本来就有新增发布，供给并未中断**；
- 同期集合内多数对象的播放量也在下行；
- 该商品的行级分发资格标记存在不合格行（缺少有效 POI 一类），但**具体卡在哪一关、为什么没有分发，当前数据域没有字段可查**。

## 可能解释

1. **共同因素（整体下行）**——与观察一致：全池同步走低时，个体的"补量无效"首先是环境的表现，不是商品的问题；
2. **分发资格 / 基础条件受限**——方向成立但不可证实：能看到资格标记不合格的行存在，看不到原因；
3. **供给不足**——不成立：供给没有中断，这正是与 CASE04 的分界；
4. **商品吸引力不足**——与效率层稳定矛盾，暂不采纳。

## 如何继续区分

1. 先查发布状态：确认供给是否真的在补——若没有收缩，"补供给解决规模不足"这条路径的前提就不成立；
2. 做集合比较：区分"个体低"与"全池低"（GUIDE13）。全池同步下行时，个体结论必须收窄；
3. 比较个体跌幅与集合跌幅：只有个体明显大于集合，才值得继续找个体原因，且仍只支持有限判断；
4. 检查效率层在补量期间的变化：量没涨、效率开始掉，说明新供给没有形成有效触达，应停止继续堆同类供给；
5. 把"分发资格受限"作为**待验证假设**明确写出：当前能看到资格标记，看不到折损原因，不能宣布它是根因。

## 与相近案例的分界

与 CASE04 的差别不在指标形态，而在两个条件：**供给是否真的中断**、**规模是否对补量有响应**。CASE04 两条都成立，本案例两条都不成立。同样的"效率好、流量低"，一个的动作是恢复供给，另一个的动作是停止把资源投在同一个方向上并说明限制。

## 得到什么经验

**"补内容"不是低流量商品的默认动作，它只对"确实存在供给收缩"的形态有效。** 供给没断、全池同跌、补量无响应三条同时出现时，正确的交付是"当前证据不支持继续补量，且限制所在机制无法用现有数据核验"，而不是再补一轮量或换一个更顺口的原因。

## 不能类比的条件

- 发布状态确实出现收缩、且规模随供给响应（CASE04 形态）→ 应继续按供给路径处理；
- 全池稳定、只有个体下行 → 个体原因的可能性更高，需要逐层排查（GUIDE15）；
- 效率层同时恶化 → 先查吸引力与承接（GUIDE05）；
- 集合比较缺失对象过多 → 中位数代表性不足，先处理数据问题（GUIDE13、GUIDE14）。
