# 动销掉量（二）：最像的原因是"价格上涨"，但它查不到

> 本案例是 **Demo 模拟案例**（synthetic case），不对应任何真实线上商品或真实运行数据。全篇只做相对描述，不使用具体数值。

## 背景

一个历史有动销的商品掉量了。与 CASE08 不同，这个商品的供给层完全正常。一种待验证的猜测是"价格涨回去了"。**本案例的要点不是找出真因，而是演示：一个看似合理的归因，在当前数据域里无法证实。**

## 观察到什么

- 订单量两期下滑；
- 发布状态：两个周期都有新增发布，供给没有收缩；
- 播放量稳定；
- 效率层出现下滑，但没有同步的可查状态变化；
- 价格字段：该商品在各周期的标价是同一个值——**没有任何跨期变化可查**；
- 券、折扣、到手价、库存、竞对价格：数据域内没有对应字段。

## 可能解释

1. **价格优势变化**——属于合理的待查方向，但**在当前数据域不可证**：标价逐期恒定，也没有到手价字段；
2. 商品热度或品类周期——需要市场基准或真实需求证据，当前没有；
3. 内容结构或素材变化——无字段；
4. 承接条件变化（券、库存、门店）——无字段；
5. 口径或记录问题——需要核对原因码后才能排除。

## 如何继续区分

1. 逐层核对可查项：供给（可查、已排除）→ 流量（可查、未跟随）→ 效率（可查、有变化）→ 状态（可查、**无变化**）；
2. 读价格相关的可查面：确认"价格无跨期变化"这一事实本身，避免误以为"没查就是没变"；
3. 检查是否存在缺失、零分母或冲突记录，先排除口径因素（GUIDE14）；
4. 到这一步，可查项已经穷尽：**剩下的候选全部落在无字段区**，正确的交付是"效率层走弱是事实，但其机制原因在当前数据域不可验证"；
5. 若需验证价格、券或库存假设，需要补充对应时期的记录。

## 与相近案例的分界

与 CASE08 同为掉量。CASE08 有明确的供给收缩证据，动作是恢复供给并观察回补；本案例可查层全部排除，动作只能是交付边界，**不能因为"历史上价格常见"就把价格写成原因**。两个案例放在一起，是为了区分"证据支持的方向"和"听起来合理的方向"。

## 得到什么经验

**归因要有当前证据，不是要有历史概率。** 一般经验可以帮助安排排查顺序，不能替代当前商品的证据。当所有可查层都排除完，诚实的结论是"当前数据域无法定因"，而不是从剩下的假设里挑一个最眼熟的。

## 不能类比的条件

- 发布状态确实收缩（CASE08 形态）→ 有可查主因，不属本案例；
- 数据域确实存在价格跨期变化 → 价格方向变为可查，应按时间关系核对而不是悬置；
- 效率层同步走弱且流量充足 → 转承接调查（GUIDE05），不是本案例的"各层都排除"形态；
- 全池同步下行 → 先处理共同因素（GUIDE13）。
