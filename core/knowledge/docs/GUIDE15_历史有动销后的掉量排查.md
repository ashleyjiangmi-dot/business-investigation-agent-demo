# 历史有动销后的掉量排查

## 适用问题

- 一个以前能出单的商品最近两轮明显掉量，先怀疑什么？
- 掉量是供给断了、流量掉了，还是效率变了？
- 同一批商品里两个都在掉量，为什么处理方式可能相反？

## 怎么理解

掉量是一个**结果**，不是一个原因。可按交易信号的历史形态把商品拆成三类分别处理，就是因为"掉量"这个词底下混着三类完全不同的处境：

- **一直无动销**：从没形成过信号，问题通常先落在"机会给够没有"（见 GUIDE09）；
- **历史有动销**：曾经有信号、现在掉了，问题落在"哪一层的输入变了"；
- **持续有动销**：信号还在，问题落在"要不要放大、放大后效率是否稀释"。

以下排查针对曾有动销、近期掉量的商品。

### 按层定位：供给 → 流量 → 效率 → 状态 → 热度

1. **供给层**：这个商品是否仍有新增内容发布。先核对供给变化，再与播放和效率方向交叉验证，不能仅凭发布状态确认原因；
2. **流量层**：播放量的两期方向。供给没变而流量掉，要转向分发与内容形态；
3. **效率层**：OPM / GPM 有没有同步走弱。流量与效率同时掉，通常不是单一环节；
4. **状态层**：商品自身的跨期状态变化。**当前数据域里唯一会真实发生变化的商品状态是"该周期是否有新增发布"**；价格字段在同一商品各周期取同一值，因此"价格回升导致掉量"这一假设在当前数据上一般**不可验证**，只能作为假设列出；
5. **热度层**：商品或品类整体热度衰退。这一层需要市场或平台大盘证据，当前数据域没有，不能作为已证实的原因。

### 三个容易犯的错

- **只看订单掉量就下"商品不行了"**：订单是四层共同作用的结果，任何一层都能造出同样的结果；
- **把其他案例的归因搬到当前商品**：排查顺序不等于原因结论，当前归因需要当前证据；
- **供给恢复后就不再看效率**：如果掉量期间效率同时恶化，补供给只会把低效放大。

### 掉量与全池变化的区分

个体掉量之前，先看它所在的集合是否一起掉。全池同步下行时，个体解释要收窄；个体跌幅明显大于集合时，也只支持有限判断，不能直接升格为个体特有的病因（见 GUIDE06、GUIDE13）。

## 常见情况

- 发布从有到无、播放跟随下滑：供给驱动的形态，第一候选是恢复供给节奏并观察规模是否回补；
- 发布正常、播放下滑、效率稳定：更像分发或流量侧变化，机制证据不可查，作为假设并说明查不到；
- 发布正常、播放稳定、效率下滑：转向吸引力与承接（GUIDE05）；
- 各层都没变但订单掉：先核对口径与缺失（unknown 原因码、记录冲突），再考虑样本与覆盖变化；
- 两个商品同掉量、层不同：动作应不同，不共享结论。

## 建议继续看什么证据

- `states`：各周期是否还有新增发布（供给是否收缩的直接方向性证据）；
- `op=diff` 分别对 M2（播放）与 M1（订单）：先分清是量的管道在缩，还是订单单独在缩；
- M4 / M5 两期：效率是否同步恶化；注意两者的行集与加权方式不同（GUIDE11）；
- `op=set_compare`：个体掉量与集合掉量是否同向（GUIDE13）；
- 单期取证：对触发判断的关键数值做同源核对；
- 价格变化、券与库存、素材与内容质量、竞对动作：当前数据域无字段，属于假设区。

## 可考虑的经营方向

- 供给层有明确收缩证据 → 恢复供给优先，设规模回补观察点；
- 供给正常但流量掉 → 列出分发与内容形态假设，说明当前不可核验的部分；
- 效率同步走弱 → 转承接与吸引力调查，不要靠补量解决（GUIDE05）；
- 任何层都没有证据 → 交付分层结论（GUIDE14），不挑一个方向当根因。

## 不能支持的判断

- 不能宣称"掉量的原因就是供给下降"，除非查到发布状态确实收缩；
- 不能把"价格回升"当作已证原因（当前数据域价格无跨期变化）；
- 不能用其他案例的原因分布支持当前个体的归因；
- 不能承诺恢复供给后规模一定回补——这是待观察的方向，不是必然结果。
