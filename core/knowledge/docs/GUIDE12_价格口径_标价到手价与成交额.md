# 价格口径：标价、到手价、券面值与人均不是同一个数

## 适用问题

- "价格上涨"指的是哪个价？
- 商品页面上的价格和用户实际付的钱为什么不一样？
- 券的面值、人均消费、商品售价能混用吗？
- 用价格算出来的成交额指标，偏差从哪来？

## 怎么理解

公开市场上"一个商品的价格"至少有五种互不相等的读法，混用它们会直接污染指标：

1. **标价 / 菜单价**：页面展示的单价，不含任何优惠；
2. **到手价 / 实付价**：用户真正付出的钱。例如模拟商品标价 80 元，使用优惠后实付 60 元；同一页面可能同时展示原价与优惠价，需要核对生效条件；
3. **券面值**：兑换凭证上印的金额。面值不等于成交价，把它当售价会把凭证金额当成商品价值；
4. **人均 / 客单价**：一次消费的均值，是**一组商品的组合结果**，不是某个 SKU 的售价。连锁火锅的主品牌人均与单人餐价格可以差出数倍；
5. **规格单价**：同一商品不同规格（重量、件数、份数）下的每单位价格。跨品牌比较必须先对齐规格。

### 为什么这条口径在经营判断里重要

成交额类指标（如 GPM）通常由订单量与价格算出。**价格取哪一种读法，直接决定这个指标的含义**：拿券面值或人均填进商品售价，等于凭空造出一个并不存在的成交价，之后所有"成交额涨跌"都不可解释。同理，跨品牌的同规格价差是真实存在的（两家烘焙店的同类吐司可以差出数倍），所以"贵"不一定意味着"卖不动"，也可能只是规格与品牌位置不同。

### 当前 Demo 数据域的价格口径

- 数据域只有**一个价格字段，含义是商品标价**；
- 该字段**在同一商品的所有模拟周期内取同一个值**，即当前数据**不产生价格跨期变化**；
- 券面值、实付价、折扣、补贴、人均消费**都没有对应字段**；
- 成交额类指标用标价参与计算，因此它表达的是"按标价折算的成交规模"，不是真实结算金额。

## 常见情况

- 用户问"这个商品是不是涨价了"：当前数据域查不到跨期价格变化，只能回答"标价可查、跨期无变化"，把"涨价导致掉量"列为不可证的假设；
- 看到两个商品标价差很多：先确认规格与品类是否可比，再谈贵不贵；
- 看到某个含券或含礼盒的商品单价异常高：确认它是否为组合套餐（可能含非餐饮实物），不能当单品价格用；
- 用公开资料补价格锚点时：区分"具体售价"与"带内取值/人均换算"，人均与券面值不得写入商品售价。

## 建议继续看什么证据

- `catalog` / 对象信息里的 `price`：商品标价（Demo 口径），以及它的来源形式登记；
- `states`：跨期属性变化——注意当前唯一会真实变化的商品状态是"该周期是否有新增发布"，价格不构成变化项；
- 类目与商品名：判断规格与组合形态，避免跨规格比较；
- 到手价、优惠力度、券库存、核销条件、补贴率：当前数据域**没有字段**，只能作为待验证假设并如实说明查不到。

## 可考虑的经营方向

- 涉及价格的经营解释（降价、涨价、优惠不足），在没有可查价格变化时，只能以假设形式进入结论；
- 需要用价格做横向比较时，先对齐规格与品类（见 GUIDE16），再比绝对值；
- 报告成交额类指标时，同时说明它由标价折算，不宣称等于实际结算金额。

## 不能支持的判断

- 不能宣称"当前商品比竞品贵/便宜"——数据域没有竞对价格、没有 Beat/Meet 字段；
- 不能把人均、券面值、补贴后到手价当商品售价；
- 不能说"价格上涨造成了掉量"，除非查到跨期价格变化（当前无）；
- 不能把 Demo 标价表述为任何真实平台的实时售价或历史价格序列。
