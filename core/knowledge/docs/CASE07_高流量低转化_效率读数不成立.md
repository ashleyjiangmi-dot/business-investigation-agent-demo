# 高流量低转化：效率读数其实不成立

> 本案例是 **Demo 模拟案例**（synthetic case），不对应任何真实线上商品或真实运行数据。全篇只做相对描述，不使用具体数值。

## 背景

一个商品播放量充足，效率指标看起来很低，团队据此准备排查承接与价格。复查时发现：**这个"低"并不是算出来的低值，而是这个指标在该周期根本没有可用读数**，被当成了"低"。

## 观察到什么

- 流量层有值且靠前；
- 效率指标返回 unknown（分母为零），而不是一个小数；
- 参与计算的行为零：该周期的行没有一条满足效率指标所需的配对条件；
- 把视线移到合计层，订单量与播放量都有正常读数；
- 结论被纠正为：**当前不能对该周期做效率判断**，而不是"效率低"。

## 可能解释

1. **口径 / 数据条件不满足**（分母为零）——与观察一致；
2. 承接真的差——尚未被检验，因为判断它需要的读数不可用；
3. 分发资格导致行被排除——可能存在（资格标记不合格的行不参与效率计算），但需要看排除行数才能判断影响规模；
4. 字段整体缺失（成交额字段全空）——与"分母为零"表现相近，原因码不同，处理也不同。

## 如何继续区分

1. 先读原因码：`zero_denominator` / `field_missing` / `period_missing` / `window_incomparable` 各自对应不同的下一步（GUIDE14）；
2. 看参与行数与排除行数：是"没有行"还是"行都被排除"，两者含义不同；
3. 换到合计层指标（订单量、播放量）确认这个周期到底发生了什么；
4. 若效率指标持续不可用 → 用合计层的相对位置替代效率判断，并明确"这是替代口径"；
5. 只有当效率读数确实成立时，才进入承接与价格调查（GUIDE05）。

## 与相近案例的分界

与 CASE06 一样表现为"量够、效率难看"。差别是：**CASE06 的弱是真实读数，需要解释；本案例的弱是读数不存在，不需要解释，需要先修口径或换指标**。把后者当成前者，会凭空生出一次承接调查和一轮不必要的动作。

## 得到什么经验

**"这个指标很差"和"这个指标这次不可用"是两句不同的话，后者不支撑任何经营结论。** 比率类指标的分母条件一旦不满足，返回的就是 unknown；把它读成低值，等于让数据缺失冒充成事实——这是 Demo 与真实业务里都最常见的一类误判。

## 不能类比的条件

- 效率指标有值且确实处于池内低位 → 属于 CASE06 或 GUIDE05 的形态；
- 只是基期或末期某一侧缺值 → 先处理缺失周期本身（GUIDE14），不要改用其他周期凑数；
- 两期窗口不可比 → 与"零分母"不同因，处理方式也不同；
- 集合比较中该对象进入缺失组 → 它不参与中位数计算，其相对位置应说成"不可比"而不是"靠后"（GUIDE13）。
