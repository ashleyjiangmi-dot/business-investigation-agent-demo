# 观察窗口与两期对比能支撑到什么程度

## 适用问题

- 只比了两个周期，可以说这个商品"在下滑"吗？
- 两期对比给出的百分比差，能撑住多远的结论？
- 什么时候"窗口不够"本身就是答案，而不是继续查的理由？

## 怎么理解

任何趋势判断都受窗口约束：**窗口决定了结论最多能走多远**。模拟数据可支持已覆盖窗口内的走势描述，不能外推到真实平台或窗口之外。

### 窗口结构决定能说什么

- 周期视图按**连续的等长模拟周期**汇总：8 个周期，每个 7 天，带起止日期。日级走势应读取日级序列，不能把周期合计均摊成每日值。
- 对同一对象、同一口径读取多期值或连续日级序列，可以描述已覆盖窗口内的走势。
- 三条限制划住它能走多远：
  1. **模拟数据、有限覆盖**——不能据此外推真实平台的同比、季节性、长期趋势或行业周期；
  2. **缺失会留下序列缺口**——对象缺某期时按 `period_missing` 处理，不把缺口当成 0 或沿用邻期值；
  3. **走势不是原因**——多期同向只说明"这段时间在往这边走"，机制仍要逐层取证（GUIDE15）。
- 同理，"分发自带滞后"这条约束在这里的含义是：一个周期里的读数还包含更早发布内容的余量，**跨期方向要连着看几期再定**，不是只看一期就下判断。

### 分发自带滞后，窗口长度不是自由参数

观察窗口要区分"是否开始有反馈"和"反馈是否稳定"。**在稳态之前做两期比较，读到的可能是滞后而不是变化。**

### 两期对比的三种失效形态

1. **窗口口径不一致**：核对长度、来源层与单位；工具判为不可比时不引用差值。日期窗口天数不同时，即使可计算整体差值，也不能称为等长或同进度比较；
2. **基期为零或极小**：百分比差会失真（基期为 0 时百分比无定义，只给绝对差）；低基数上的高增速不能读成高增长；
3. **记录层问题**：同一对象同一周期存在互相冲突的多条记录时差值被拒；对象名称跨期不一致时比较直接停止。

这三种情况下，"下降 x%"不是一个可以引用的数。

### 覆盖变化的位置

参与统计的行数或对象数在两期之间变化，影响的是**这次比较可不可靠、有没有代表性**，它解释的是比较本身，**不能写成指标下降的原因**。同理，整个集合都在下行时，个体下滑的解释要收窄；个体跌幅大于集合，也只支持有限判断。

## 常见情况

- 两期差值方向明确、幅度大、且两期可比 → 可以报告"变化"，但原因仍需逐层证据（GUIDE01、GUIDE15）；
- 两期差值小、在噪声量级内 → 报告"未见明显变化"，不要为了给出结论放大微小差异；
- 商品处于冷启动早期（见 GUIDE09）→ 优先说明窗口还没走完，而不是解释表现；
- 返回 unknown 且带原因码 → 按原因码处理（见 GUIDE14），不要把 unknown 当 0 或不一致的方向。

## 建议继续看什么证据

- `op=diff` 的返回结构：绝对差与百分比差都在，基期与末期各自带完整口径——**读差值时把两期的口径块一起读**，不要只取百分比；
- 可比性信号：`window_incomparable`、`record_conflict`、`identity_inconsistent` 三类原因码，任一出现即停止趋势解释；
- 参与行数与排除行数：`n_rows`、`contributing_rows`、`excluded_missing`、`eligible_rows` 决定这个数是"多少东西算出来的"；
- 时间覆盖：周期目录、日期窗口起止与粒度，决定能读取多长的走势；
- 小时级明细、真实平台同比基准及覆盖范围外的历史：当前不可查，不能据此作确定判断。

## 可考虑的经营方向

- 窗口不足以区分"变差"与"还没稳定" → 延长观察而不是加动作；
- 需要更长时间形态 → 逐期取该对象的值或逐对相邻差，把窗口内走势连起来报告，同时说明一共只有这么几期、缺哪期；
- 两期不可比 → 先处理可比性，再决定是否还能引用差值；
- 覆盖变化 → 只在"这次比较可靠吗"这一层表述，不进入原因层。

## 不能支持的判断

- 不能把模拟窗口内的变化表述为真实平台的同比或环比表现，也不能外推为季节性、长期趋势或市场趋势；
- 不能把百分比差直接当成降幅的因果解释（差异是结果，不是原因）；
- 不能在基期为 0 时使用百分比；
- 不能用"窗口不够"作为不再查询的理由——先确认还有哪些可查没查（见 GUIDE14）。
